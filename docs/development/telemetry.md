# Обезличенная диагностика ошибок

Отчёт Sentry собирается заново по разрешённым полям на последнем этапе перед отправкой. Это защищает от появления пользовательских данных в новых полях SDK: исходные сообщения, произвольные теги, contexts, extra, breadcrumbs, запросы, журналы, сведения о потоках и имя компьютера не копируются. В браузерной части также удаляются вложения и отключены стандартные интеграции; включены только глобальный перехват ошибок и дедупликация. Версия приложения и канал берутся из сборки.

При неожиданном сбое очистки браузерный обработчик возвращает `null` и отбрасывает событие. Исключение из `beforeSend` SDK может переслать как внутреннюю ошибку в обход `beforeSend`, поэтому повторно отправлять ошибку очистки нельзя. Нестроковые сообщения ошибок обозначаются как `unclassified` без преобразования в строку.

Поле пользователя содержит только `ip_address: 0.0.0.0`. Простое удаление `user` не запрещает серверу Sentry вывести IP и географию из входящего транспортного запроса; явный нулевой адрес подавляет такое дополнение. См. [официальное описание Sentry](https://github.com/getsentry/sentry-docs/blob/master/docs/platforms/react-native/common/data-management/data-collected.mdx).

## Техническая причина

Исходный текст используется только локально для выбора фиксированной категории. Неизвестные сообщения превращаются в `unclassified`: это сознательное ограничение приватности. Категория не является доказательством первопричины, а обозначает распознанный технический шаблон.

В JavaScript сохраняются только стандартные типы ошибок. Распознаются коды минифицированных ошибок React, доступ к несуществующему свойству, вызов значения, которое не является функцией, неизвестная переменная, переполнение стека и известные сообщения сетевой ошибки. Аргументы URL декодера React и имена переменных не отправляются. Для отклонённого Promise отдельно сохраняется только результат `typeof` причины, без её содержимого, имён ключей и пользовательского имени класса.

В Rust распознаются `Result::unwrap`, `Option::unwrap`, выход за границы, нарушения assert, конфликт заимствования, деление на ноль и сбой setup Tauri. Значения `Err`, аргументы assert и произвольный payload паники не отправляются.

## Место сбоя

Браузерные кадры содержат только путь JS-ресурса `assets/*.js` из упакованного приложения, строку и столбец. Адрес WebView заменяется на `app:///`, query и fragment удаляются. Имена функций, локальные переменные и строки исходников не копируются. Ссылки на sourcemap сохраняют только нормализованный путь и debug ID; это оставляет возможность символизации загруженными картами исходников.

При отсутствии пригодного исходного стека создаётся отдельный контекст `diagnostic_observation` со стеком обработчика отправки. Он помогает определить работающий bundle, но не указывает место создания Promise. У отклонения без `Error` синтетические кадры SDK не выдаются за исходный стек. Поле `diagnostic.stack` сообщает `original` или `unavailable`.

В Rust отдельный extractor добавляет `panic.file`, `panic.line` и `panic.column` непосредственно из места паники. Он использует штатный захват backtrace в момент паники. Стандартные интеграции отключены; явно подключены debug images, обработка backtrace и единственная интеграция паники с extractor. Добавлять второй `PanicIntegration` поверх стандартного нельзя: SDK использует первый экземпляр и игнорирует extractor второго.

Пути Rust сокращаются до части внутри `src/`, без домашней папки, registry и абсолютного префикса. Сохраняются технические имена функций из бинарника и числовые адреса кадров. Локальные переменные, исходный текст, регистры, пути библиотек и имена потоков не передаются. Debug images сохраняются только для бинарников приложения: разрешённые имена, адреса и debug ID позволяют использовать опубликованные символы без локальных путей.

Пути разных Rust-крейтов могут совпасть после удаления префикса: различать такие кадры помогают символы функций и отладочные символы. При недоступных символах остаются адреса, а у паники — отдельное место из extractor. Паника, случившаяся до инициализации телеметрии, не захватывается. Старые события не получают новую диагностику задним числом.
